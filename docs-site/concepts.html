Three concepts that carry the product

Directive’s install story is dense on purpose. These three ideas are enough to orient before you dive into skills and strategies.

A

Layered standards (how agents behave)

Preferences and rules cascade. Higher layers win. Agents lazy-load only what the task needs.

  1. USER.md — personal overrides (always wins for fields it defines).
  2. PROJECT-DEFINITION xBRIEF — project identity and policy.
  3. Language / tool files — stack-specific standards.
  4. main.md — general agent behavior.

Requirements (“what to build”) stay on a separate ladder: specification and scope xBRIEFs, not mixed into the behavior cascade.

B

xBRIEF scope lifecycle (what is in progress)

Work is durable JSON state, not chat memory. Scope briefs move through lifecycle folders with matching plan.status: 

proposed → pending → active → completed
                 ↘ cancelled / failed

Use framework verbs (scope:promote, scope:activate, scope:complete, …) rather than moving files by hand. Implementation intent is gated (xbrief:preflight) so agents do not edit code before a running brief exists.

C

Deterministic gates (proof over prose)

High-impact behavior is enforced by checks, not only by README wording:

  • task check — pre-merge aggregate gate
  • directive doctor — install / deposit diagnosis
  • Branch, encoding, session-ritual, and story-ready verifiers
  • Hooks and CI that refuse default-branch and same-ref PR mistakes

Rule strength order: deterministic checks > Taskfile targets > xBRIEF policy > RFC2119 markers > plain prose.

Category fit

Directive is the practice layer row: standards + durable work state + gates in the repo. Coding hosts run the agent. Skill packs improve one session. App orchestrators run multi-agent products in app code. Full four-way map: docs/CATEGORY.md.

How the loop fits together

At inception: concept → strategy analysis → specification + proposed scopes. Every session after that: session start → triage/refine → slice → swarm → review/fix → ship, with new issues feeding triage again.

Diagram and stage-to-command map: directive-lifecycle.md. Maintainer concepts deep-dive: docs/CONCEPTS.md.

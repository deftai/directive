Gates

Quality gates

Directive prefers enforceable checks over “please remember” guidance. Use narrow gates while iterating; run the full merge gate before a PR.

Everyday gates

Gate What it answers
directive doctor Is the install / deposit healthy? What is the single next command?
task check Is this change merge-ready for the framework (or consumer include)?
task xbrief:preflight -- Is this scope brief activated and ready before code edits?
task verify:branch Are we on a feature branch when policy requires it?
task verify:encoding Did non-ASCII content survive edits without mojibake?

Merge chokepoint vs iteration lane

Every change must pass the full gate at least once before merge. While iterating, prefer affected tests and focused verify:* targets. Before push / PR, run the full aggregate once. 

# iteration (examples)
task verify:branch
task xbrief:preflight -- xbrief/active/.xbrief.json

# merge chokepoint
task check
# or, when preparing a framework PR:
task check:merge

Branch policy

Default policy blocks direct commits to master/main and refuses PRs whose head ref equals the base ref. Enforcement spans git hooks, task verify:branch, and CI (branch-gate.yml). See the repository README branch-policy section for the typed plan.policy.allowDirectCommitsToMaster flag and emergency bypass.

Hosted agent workflows (review-cycle, swarm, pre-pr skills) assume these gates stay green. Skipping them is how silent drift returns.

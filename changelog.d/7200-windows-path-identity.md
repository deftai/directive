section: Fixed
- windows: path identity no longer treats the 8.3 short, lowercase and long spellings of one worktree as two trees. `session/git.ts` adds `canonicalPathIdentity` (`realpathSync.native`, nearest existing ancestor for a missing path, no case fold) and `samePathIdentity`; on win32 `gitCommonDir`, `worktreePath` and `worktreePathOrNull` return that form, and hook root admission, occupancy, the ritual check, owner-liveness, the main-worktree test, linked-worktree prep, dest-place, story binding, the pre-dispatch alias key, spawn and child occupancy and the cohort worktree map compare through it. The write fence (`isOutsideProjectRootWrite`, `toProjectRelativePosix`) treats an 8.3 or other-case spelling of a path inside the root as inside, so story file_scope and denyPaths keep applying. Worker-auth and spawn-reservation keys use the same form; a record written before this fix under another spelling is not looked up, and an old lowercase-keyed worker-auth entry can still be refused as a malformed assignment. POSIX is unchanged (#7200).

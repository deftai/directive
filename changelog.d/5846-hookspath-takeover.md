section: Fixed
- `directive install` and `directive install --repair` now say in their plan when this repository already uses other Git hooks (a global or local `core.hooksPath`, or hooks in `.git/hooks`), and switch it to Directive's `.githooks` only after you approve that one plan. The output then says which hooks no longer run here, with a tip about hook managers such as Husky or Lefthook. Before, a global `core.hooksPath` made install, repair and upgrade fail with "setup completed with conflicts" and nothing said how to fix it. Refs #4960, #5846.
- `directive upgrade` and automatic setup never change another `core.hooksPath`. They now finish, report "Git hooks inactive" and name `directive install --repair`; `directive doctor` names the same fix and where the setting comes from.
